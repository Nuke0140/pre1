You are continuing implementation of the existing PreOne Preschool Management Platform.

This is NOT a greenfield project.

M00 — Preschool Creation & Setup has already been implemented.

The next objective is to connect M00 to the existing PreOne bounded contexts and complete the end-to-end preschool lifecycle so that PreOne does not merely store information, but actually operates the preschool workflow from configuration through daily child care, learning, parent communication, finance, reporting, and year-end continuation.

============================================================
0. ABSOLUTE RULES
============================================================

DO NOT:

- redesign the existing architecture
- replace existing bounded contexts
- create duplicate Student, Parent, Teacher, Academic Year, Branch, Fee, Attendance, Notification or Curriculum systems
- bypass existing RBAC
- bypass existing audit
- bypass tenant/school/branch/academic-year isolation
- create parallel APIs where an existing API already exists
- create a second business-rule engine
- create a second notification engine
- create a second configuration system
- directly query another bounded context's tables if the architecture forbids it
- silently modify locked ADR decisions
- remove existing working functionality

FIRST inspect and understand:

- PreOne Master PRD
- PreOne DDD
- PreOne BRC
- PreOne ADRs
- PreOne ERD/database schema
- PreOne API Contract Catalog
- UI Design Philosophy
- Parent Portal
- Teacher Portal
- M00 Implementation Impact Map
- Existing implemented M00 code

Then produce an implementation impact map before coding.
